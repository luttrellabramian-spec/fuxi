### H3 · StreamComplete LLM 实例替换加锁 · 🟢 30 行改动

**文件**：`python/src/grpc_server.py:214-228`

**当前问题**：
```python
if (target_model != current_model or ...):
    if hasattr(self.engine.llm, '_client') and self.engine.llm._client is not None:
        try: self.engine.llm._client.close()
        except Exception: pass
    self.engine.llm = LLMClient(...)
```
多请求并发时，旧客户端可能正在被另一线程使用，被 close 后下一请求拿到野指针。

**修复方向**：
- 方案 A：每个请求 `new LLMClient()`，不替换 `self.engine.llm`（推荐）
- 方案 B：加 `threading.Lock` 保护整个替换块
- 方案 C：把 LLM 客户端存到 `threading.local()`

**选 A**，最简单无锁：
```python
# 不动 self.engine.llm
llm = LLMClient(api_key=config["api_key"], base_url=config["base_url"], model=target_model)
for event in llm.stream_run(messages, ...):
    yield ...
```
需要把 `stream_run` 逻辑从 `FuxiEngine` 抽到 `LLMClient`，或加一个不依赖 `self.engine.tool_registry` 的 LLMClient.stream_chat(messages)。

**验证**：
- 写一个并发测试：10 个线程同时切换 model/base_url，断言没有 race
- e2e_verify.py 10/10 PASS

### H8 + H9 · Authorization 链补全 · 🟡 一致性修复

**文件**：
- `typescript/src/gateway.ts:80-81`（WS）
- `typescript/src/gateway.ts:464, 496, 526, 553, 590, 638, 665, 702`（6 memory 路由）

**修复**：抽一个 `buildMetadata(req)` helper
```ts
function buildMetadata(req: Request): grpc.Metadata {
  const md = new grpc.Metadata();
  // 1. 客户端 Authorization 头（最高优先级）
  const auth = req.headers['authorization'];
  if (auth) md.add('authorization', Array.isArray(auth) ? auth[0] : auth);
  // 2. 客户端 X-Base-Url / X-Model
  const base = req.headers['x-base-url'];
  if (base) md.add('base-url', Array.isArray(base) ? base[0] : base);
  const model = req.headers['x-model'];
  if (model) md.add('model', Array.isArray(model) ? model[0] : model);
  return md;
}
```
所有路由（含 WS、memory）统一用 `buildMetadata(req)`，移除散落的 `new grpc.Metadata()`。

WS 路径略不同：客户端无法在握手时设 Authorization 头（WebSocket API 限制），需要用 Sec-WebSocket-Protocol 子协议或在 first message 携带。

**验证**：
- e2e_verify.py 加 `/memory/*` 路径检查（无 LLM key 也能调，因为 memory 操作不需 LLM）
- 手动测：WS `/ws/chat` 不带 Authorization 头应返回错误（如果鉴权开）

### H4 · 沉默 except 系统性改造 · 🟡 大手术

**文件**：整个 `python/src/`（130+ 处 `except Exception`）

**步骤 1**：定义 `swallow_and_log` 装饰器
```python
# python/src/utils/silent.py
import logging
import functools
from typing import Callable

def swallow_and_log(logger: logging.Logger, msg: str = "swallowed exception"):
    """装饰器：except 块内静默失败改为 logger.warning。
    
    用法：
        @swallow_and_log(logger, "tool tracker record failed")
        def record(...):
            ...
    """
    def decorator(func: Callable):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            try:
                return func(*args, **kwargs)
            except Exception as e:
                logger.warning("%s: %s", msg, e, exc_info=False)
        return wrapper
    return decorator
```

**步骤 2**：扫 `except Exception: pass`，逐个替换
```python
# 之前
except Exception:
    pass
# 之后
except Exception as e:
    logger.warning("xxx failed: %s", e, exc_info=False)
```

**步骤 3**：识别"故意静默"的位置（如测试夹具），不强行改

**步骤 4**：加 metrics
- `silent_failures_total{module, function}` counter
- Prometheus 输出（gateway.ts /metrics 已存在）

**验证**：
- 161 单测全 PASS
- grep `except Exception: pass` 应只剩测试代码
- 故意制造一个失败，看日志有 WARNING、metric 增加

**修复**：
1. `_rebuild_fts` 改后台线程：
```python
def _ensure_fts(self):
    if not self._fts_dirty:
        return
    # 不阻塞，直接调度后台 rebuild
    self._schedule_rebuild()

def _schedule_rebuild(self):
    if self._rebuild_thread and self._rebuild_thread.is_alive():
        return  # 上一个还在跑，跳过
    self._rebuild_thread = threading.Thread(
        target=self._rebuild_fts, daemon=True
    )
    self._rebuild_thread.start()
    self._fts_dirty = False
```

2. selector 加缓存：

def _retrieve_memories(self, ...):

        return cached
    ...

## 跨阶段建议

1. **每个 Phase 结束跑全套回归**：
   - `python -m pytest -q` （python 单测）
   - `cd typescript && npm run build` （TS 编译）
